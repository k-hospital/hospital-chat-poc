### 담당 범위
| 포함 (나) | 제외 (다른 담당자) |
|---|---|
| 마이크 녹음 → STT (`/v1/stt`) | 메인 화면 자체, 메뉴·의도 분류, 한국어 챗봇 |
| 음성 번역: 외국어 음성 → 외국어 답변 (`/v1/chat/foreign`, D안) | 진료 예약, 본인인증 |
| 상담원 연결 **이용자 쪽 화면** (대기 순번, 실시간 대화창) | **상담원용 화면** `/agent` |
| 외국인 ↔ 한국어 상담원 **메시지 자동번역** | 콜백 접수 |
| 대기열·WebSocket 서버 + 상담원 화면용 접속 규격 문서 (**제안, 합의 필요**) | |

### 연동 방식: API + React 부품 제공 (메인 코드는 직접 수정하지 않음)
```
[메인 화면 (메인 담당자)]
  ├─ 마이크 버튼 onClick ─► useVoiceInput() 훅 / <MicButton>   (내 부품)
  │     녹음(MediaRecorder) → POST /v1/stt → {text, language}
  │       language = ko    → 메인 챗봇 입력으로 넘김 (메인 담당)
  │       language = en/zh → POST /v1/chat/foreign → 그 언어로 답변 (내 API)
  │
  └─ 상담원 연결 onAgent ─► <AgentChatPanel>   (내 부품)
        POST /v1/handoff → {ticket, queue_position}
        WebSocket /v1/handoff/ws/{ticket} → 실시간 대화
        외국어 ⇄ 한국어 자동번역 (Qwen3.6), 원문 보기 지원
                     ▲
        [상담원 화면 /agent (다른 담당자)] — 같은 WebSocket 규격으로 접속
```

### 배포 전제 (중요)
- 실제 동작은 **사내 서버에 HTTPS로 배포**된 화면에서만 가능
  - Netlify(외부 https) 화면 → 사내 http 서버 호출은 브라우저가 차단(Mixed Content), 외부망에서는 사내 주소(172.30.x.x)에 닿지 않음
  - 마이크는 https 또는 `localhost`에서만 허용
- 개발·테스트: PC에서 `localhost`로 실행 (사내망 PC라 사내 서버 호출 가능)
- 운영: 메인 화면 + 내 백엔드를 사내 서버 한 도메인(https) 아래 배포 — 인증서·앞단 웹서버는 인프라/메인 담당자와 결정

## 3. 메인 화면 연동 규격 (메인 담당자에게 전달할 내용)

### 호출 URL
```
https://<서버>/global/?lang=en
```

| 파라미터 | 값 | 설명 |
|---|---|---|
| `lang` | `en` \| `zh` (추후 `mn`) | 화면·답변 언어. 없거나 잘못된 값이면 `en` |
| `embed` | `1` (선택) | iframe으로 띄울 때 상단 헤더·닫기 버튼 숨김 |

### iframe으로 띄울 경우
```html
<iframe src="https://<서버>/global/?lang=en&embed=1" allow="microphone"></iframe>
```
- `allow="microphone"` 없으면 음성 입력이 동작하지 않음.
- 메인 화면과 **같은 도메인(HTTPS)** 권장. 다른 도메인이면 내 모듈 응답 헤더에 `Content-Security-Policy: frame-ancestors <메인 도메인>` 설정 필요.

### 부모 창으로 보내는 이벤트 (postMessage, 협의 필요)
| 이벤트 | 시점 | 메인 화면 처리 (제안) |
|---|---|---|
| `{type: "global-chatbot:close"}` | 사용자가 닫기/뒤로 | iframe 닫기 |
| `{type: "global-chatbot:handoff", lang}` | "상담원/국제진료센터 연결" 클릭 | 메인의 상담원·콜백 흐름 호출 |

> 상담원 연결은 범위 밖이므로, 내 화면에는 **국제진료센터 연락처 안내 + 위 이벤트 발송**까지만 구현.

## 5. API

경로 접두사 `/global/api/v1` (리버스 프록시 경로와 일치시킴).

### `GET /global/api/v1/config`
```json
{ "languages": ["en", "zh"], "default": "en", "stt_enabled": true, "max_message_chars": 500, "max_audio_seconds": 30 }
```

### `POST /global/api/v1/chat`
요청
```json
{ "lang": "en", "message": "How much is parking?" }
```
응답
```json
{
  "lang": "en",
  "answer": "Parking fees are ...",
  "query_ko": "주차 요금이 얼마인가요?",
  "sources": [ { "title": "주차 안내", "category": "병원 이용", "source_url": "https://...", "score": 0.91 } ],
  "notice": "This is a machine-translated guide. ..."
}
```
- `query_ko`: 디버깅·품질 확인용 (화면에는 "검색에 사용된 한국어 질문" 접힌 영역으로 표시할지 검토).
- 오류: `{ "error_code": "LLM_TIMEOUT", "message": "<사용자 언어 안내문>" }` — **내부 IP·원문 에러 노출 안 함**, 상세는 서버 로그(질문 본문 제외)에만.

### `POST /global/api/v1/stt`
- `multipart/form-data`: `audio`(webm/opus, 최대 30초·약 1MB), `lang_hint`(선택)
- 응답
```json
{ "text": "Where is the emergency room?", "language": "en", "duration": 3.2 }
```
- 음성 파일은 **저장하지 않음** (메모리에서 Whisper로 전달 후 폐기).

### `GET /global/api/v1/health`
- `{ "status": "ok" }`만 반환 (내부 구성요소 주소 노출 안 함).

### 스트리밍(SSE)
- 1차는 **비스트리밍**으로 구현해 품질부터 확인. Qwen3.6 응답이 길어 체감이 느리면 `POST /chat/stream`(SSE) 추가. 메인 담당자의 SSE 형식이 정해지면 맞춤.

## 6. 외국어 Q&A 처리 흐름

```
1. 입력 검증: 500자 제한, 빈 문자열 거부
2. 질문 언어 판별 (문자 범위 규칙, LLM 호출 없음)
     한글 → ko / 한자 → zh / 키릴 → mn / 라틴 → en
   - 화면 언어(lang)와 질문 언어가 다르면 → 답변은 "질문 언어"로 (사용자가 실제로 쓴 언어 우선)
3. 한국어 번역 (ko면 생략)
     Qwen3.6, temperature 0, enable_thinking False, max_tokens 200
     프롬프트: "병원 안내 검색용으로 한국어로 번역. 번역문만 출력. 증상·신체 부위는 한국 병원에서 쓰는 일반 용어로."
4. 검색: 한국어 질문으로 기존과 동일 (dense+sparse → RRF 후보 10 → 리랭커 상위 N)
     - 리랭커 query도 한국어 질문 사용
5. 답변 생성: Qwen3.6
     - 시스템 프롬프트: 기존 규칙(지어내기 금지, 진단·병명·치료법 금지, 증상 질문 3단 순서)을 대상 언어로 답하도록 수정
     - 교수 이름·진료과·장소 이름은 "영문/중문 표기 (한국어 원문)" 형식 → 병원 현장에서 한국어로 찾을 수 있게
     - 참고 자료 제한 완화: 1개당 3,000자, 전체 12,000자, 리랭커 상위 5개 (설정값, 품질 보고 조정)
6. 응답 조립: answer + sources(제목은 한국어 원문 그대로, 링크 유지) + 언어별 면책 문구
```

### 언어별 고정 문구 (예시, 최종 문구는 검토 필요)
| 키 | en | zh |
|---|---|---|
| 면책 | AI guidance is for reference only and is not a diagnosis. | AI 指引仅供参考，并非诊断。 |
| 번역 안내 | This answer is machine-translated. For accurate information, please contact the International Healthcare Center. | 本回答为机器翻译。如需准确信息，请联系国际医疗中心。 |
| 응급 | In an emergency, call 119 or visit the emergency room. | 紧急情况请拨打119或前往急诊室。 |

- 국제진료센터 연락처는 크롤링 데이터에서 확인 후 **설정 파일**에 넣음 (하드코딩 금지).
- 응급 키워드(언어별 목록: chest pain, can't breathe, 胸痛, 呼吸困难 …) 감지 시 답변 위에 응급 안내 우선 표시.

### 호출 수·지연 예상
- 질문 1건 = Qwen3.6 2회(번역 짧게 + 답변) + 임베딩 2 + Qdrant 1 + 리랭커 1
- 예상 응답 시간 4~10초 (Qwen3.6 GPU 부하에 따라). 실측 후 SSE 여부 결정.

## 8. 음성인식 (STT)

### 서버 (2026-10-02 배포 완료)
- 주소: `http://<AI서버1>:8090/v1/audio/transcriptions` (OpenAI 호환, multipart: `file`, `model`, `language`, `response_format`)
- 모델: `deepdml/faster-whisper-large-v3-turbo-ct2` (int8). 지원 언어에 ko·en·zh·mn 포함 (mn 품질은 미검증)
- 서빙: speaches `ghcr.io/speaches-ai/speaches:latest-cpu`, `~/docker-compose.yml`의 `whisper-stt` 서비스
- 배치: **.31 CPU** (GPU 여유 부족으로 인프라가 CPU 지정). `cpus: 12`, `WHISPER__CPU_THREADS=12`, `WHISPER__TTL=-1`(모델 상시 로딩)
- 실측: 합성 음성 10.6초 → 약 5초, 실제 녹음 m4a 3.6초 "그 병원은 어디에 있죠?" → 5.0초·정확. m4a 변환 없이 수신
- 인증 없음 → 브라우저가 직접 호출하지 않고 반드시 백엔드 `/stt` 경유
- 개선 여지: 의료 용어 오인식 시 `prompt` 힌트, 너무 느리면 작은 모델로 교체

### 흐름
```
마이크 버튼 누름 → 브라우저 MediaRecorder(webm/opus) 녹음 (최대 30초, 버튼 다시 누르면 종료)
  → POST /global/api/v1/stt (백엔드가 Whisper로 프록시 — 브라우저가 Whisper 서버에 직접 붙지 않음)
  → { text, language } 수신
  → 입력창에 텍스트 채움 (자동 전송 안 함, 사용자가 확인 후 전송)
  → 감지 언어 ≠ 화면 언어면 "화면 언어를 中文으로 바꿀까요?" 작은 안내
```
- **브라우저 Web Speech API 사용 금지** (음성이 외부 서버로 전송됨).
- **HTTPS 필수**: 브라우저는 HTTPS(또는 localhost)에서만 마이크 허용. 개발 중에는 `localhost`로 테스트 가능, 팀원 접속·운영은 HTTPS 필요.
- 마이크 권한 거부·미지원 브라우저면 버튼 비활성 + 안내.
