# 검색 데이터 파이프라인 (병원 안내 챗봇)

최종 갱신: 2026-10-07 · **관리 담당: 번역·음성인식 담당자** (검색 데이터는 이 담당자만 적재한다)

Qdrant `hospital_chunks` 컬렉션(`http://<AI서버1>:6333`)은 한국어 챗봇과 외국어 모듈이 **같이 조회**한다.
여기를 바꾸면 모든 챗봇에 즉시 반영되므로, 아래 순서와 주의사항을 지킨다.

## 1. 파일

| 구분 | 파일 | 설명 |
|---|---|---|
| 원본 | `chunks.json` | 홈페이지 크롤링 1,911조각 (길이 기준 분할, 직접 적재하지 않음) |
| 원본 | `홈페이지 크롤링/rag_chunks.jsonl` | 섹션(`##`) 단위 352조각 + context. 113페이지 |
| 원본 | `ish_doctors.json` | 의료진 171명 (진료과·이름·전문분야) — **의료진 정보의 기준** |
| 가공 | `rechunk.py` | `chunks.json` → `chunks_rechunked.json` (페이지 복원, 의료진 목록·상세·논문·수련교육부 제외, 구조 기준 재분할, 센터 의료진 1명=1조각) |
| 가공 | `combine_chunks.py` | `rag_chunks.jsonl` + 재청킹 결과 중 빠진 페이지 → **`chunks_combined.json`** |
| 운영 데이터 | `chunks_combined.json` | 현재 Qdrant에 들어간 데이터의 원본 (645조각 → 정제 후 640) |
| 가공 | `make_lay_terms.py` | 의료진 전문분야 → 환자가 쓰는 "쉬운 말"(부위·증상) 초안을 Qwen3.6으로 생성 → `doctor_lay_terms.json` + 검수용 `doctor_lay_terms_검수.csv`. 기존 파일이 있으면 덮어쓰지 않음(`--force`), `--clean-only`는 LLM 없이 중복만 정리 |
| 가공 | `doctor_lay_terms.json` | **사람 검수를 거친** 쉬운 말 (`reviewed: true`만 적재에 사용). 149명 적용, 21명 "없음"(영상의학과 등) |
| 적재 | `insert_chunks_to_qdrant.py` | 정제 + dense/sparse 임베딩 + Qdrant 적재. 의료진 170명을 1명=1조각으로 추가(`--lay-terms`면 "관련 증상·부위" 줄 포함) → **총 810건** (2026-10-07) |
| 측정 | `../tests/check_symptom_hit.py` + `symptom_cases.json` | 증상 25건: 상위 5개에 기대 진료과·의료진이 있는지 (한국어·영어·중국어) |
| 측정 | `../tests/check_general_hit.py` + `general_cases.json` | 일반 안내 12건 (주차·서류·검진 등) |

**공유하지 말 것**: `../로컬 AI 서버정보.txt`(SSH 비밀번호 평문), `sparse_cache.jsonl`·`chunks_cleaned*.json`(실행 때 생성), `*.bak*`

## 2. 실행 순서 (이 폴더에서, PowerShell)

```powershell
$env:PYTHONIOENCODING='utf-8'

# ① 가공 (원본이나 가공 규칙을 바꿨을 때만)
python rechunk.py
python combine_chunks.py

# ①-2 의료진 쉬운 말 (ish_doctors.json이 바뀌었을 때만) → CSV 검수 → doctor_lay_terms.json 반영 (reviewed: true)
# python make_lay_terms.py --force      ※ 검수 내용이 지워지니 주의

# ② 테스트 컬렉션에 먼저 적재 → 측정 (운영 데이터 안 건드림)
python insert_chunks_to_qdrant.py --src chunks_combined.json --lay-terms doctor_lay_terms.json --collection hospital_chunks_test --cache sparse_cache.jsonl
cd ..\tests
$env:QDRANT_COLLECTION='hospital_chunks_test'; python check_symptom_hit.py; python check_general_hit.py
$env:QDRANT_COLLECTION='hospital_chunks';      python check_symptom_hit.py; python check_general_hit.py   # 비교용(현재 운영)
cd ..\data

# ③ 좋아졌으면 운영에 적재 (캐시가 있으면 약 10초, 없으면 약 2분)
python insert_chunks_to_qdrant.py --src chunks_combined.json --lay-terms doctor_lay_terms.json --cache sparse_cache.jsonl

# ④ 테스트 컬렉션 정리 (Qdrant 대시보드 http://<AI서버1>:6333/dashboard 에서 hospital_chunks_test 삭제)
```
- **`--lay-terms`를 빼먹으면 쉬운 말 보강이 빠진 데이터가 운영에 올라간다** (한국어 그대로 의료진 적중 96% → 36%로 되돌아감)
- `--dry-run`: 서버 호출 없이 정제 결과만 확인 (`chunks_cleaned*.json` 생성)
- `--cache sparse_cache.jsonl`: sparse 계산 결과 재사용 (중단 후 이어하기, 테스트→운영 적재 시 재계산 없음)

## 3. 주의사항

1. **적재 중 약 2분간 모든 챗봇 검색이 실패한다** — 적재 스크립트가 컬렉션을 지우고 다시 만든다. 운영 시간 외에 하거나 미리 알릴 것.
2. **임베딩 서버를 바꾸지 말 것** — dense `<AI서버2>:8082`, sparse `<AI서버2>:8083`(예비 `<AI서버1>:8091`, 같은 값)이 스크립트 기본값. 다른 모델로 만든 벡터는 질문 쪽과 맞지 않는다.
3. **예전 `chunks.json`을 그대로 적재하지 말 것** — 1,027건짜리 예전 구성으로 돌아간다. 항상 `chunks_combined.json`으로.
4. **바꾸기 전후 측정** — 증상(진료과·의료진 적중)과 일반 안내가 둘 다 나빠지지 않았는지 확인.
5. 데이터 변경 사항은 팀(메인 담당자)에게 공유.

## 4. 현재 품질 (2026-10-07, 운영 810건, 의료진 쉬운 말 보강 후)

| 질문 (상위 5개 기준) | 보강 전 진료과 / 의료진 | **보강 후 진료과 / 의료진** |
|---|---|---|
| 증상 25건, 한국어 그대로 (확장 없음) | 60% / 36% | **96% / 96%** |
| 증상, 한국어 + 질문 확장 | 100% / 84% | **100% / 100%** |
| 증상, 영어·중국어 번역만 | 56~60% / 36% | **96% / 96%** |
| 증상, 외국어(번역+확장, D안) | 100% / 80~92% | **100% / 100%** |
| 일반 안내 12건 (한국어 그대로) | 92% | **92%** (변화 없음) |

- "손목이 아파요" 한국어 그대로: 보강 전엔 김상희 교수(수부외과) 조각이 어느 검색 단계에도 없었음 → 보강 후 **dense·sparse·후보·리랭크 모두 1위** (`trace_doctor_search.py`)
- 측정 원본: `../tests/results/2026-10-07_쉬운말보강/` (`sym_`=기본 측정, `cmp_`=검색 설정 비교, `gen_`=일반 안내)
- '의료진까지'는 기대 진료과의 의료진 조각이 상위 5개에 있는지만 본다 (세부 전문의 일치는 손목만 직접 확인)

**검수 때 남긴 숙제** (초안 그대로 승인함 — 다음 검수 때 고칠 것)
- 박희완 교수(소아 정형외과)에 "손목 통증·발목 통증" 등 성인과 겹치는 표현 → "아이 손목 통증"처럼 소아로 한정 권장
- 김상희 교수 전문분야 '주관절(팔꿈치)'에 해당하는 표현 없음
- 응급의학과 14명 대부분에 "심한 출혈·실신" 등 → 외래 예약 대상이 아니므로 "없음" 처리 권장
- 진료과 전체에 같은 표현이 들어간 경우(심장내과 전원 "가슴 통증" 등)는 과 안에서 교수 구분이 안 됨

### 검색 설정 (2026-10-06 측정 → 외국어 모듈에 반영, 한국어 챗봇도 적용 권장)
진단(`../tests/trace_doctor_search.py`): 리랭커가 번역문("손목이 아파요")만 보면 "수부외과" 전문의 조각을 **후보 중 꼴찌**로 보냄. 후보 10개 안에 못 드는 경우도 5회 중 3회.

설정 비교(`check_symptom_hit.py --compare-settings`, 증상 25건, 진료과/의료진 적중):

| 경로 | 현재(후보10, 리랭크=번역문) | **후보30, 리랭크=번역문+키워드** |
|---|---|---|
| 한국어 + 질문 확장 | 25 / 21 | **25 / 23** |
| 영어 | 25 / 22 | **25 / 25** |
| 중국어 | 25 / 23 | **25 / 25** |

- 일반 안내 12건 저하 없음 (`check_general_hit.py --compare-settings`). 후보만 30으로 늘리고 리랭크를 번역문으로 두면 오히려 나빠짐(영어 의료진 17/25)
- 외국어 모듈 반영: `hospital_chatbot/backend/config.py` `HYBRID_SEARCH_LIMIT=30`, `RERANK_WITH_KEYWORDS=1`. 응답 시간 변화 거의 없음(1.3~3.2초)
- 반영 후 "My wrist hurts" 영어 5 + 중국어 3회 답변 중 **김상희 교수 언급 6/8** (이전엔 대부분 다른 교수·발목/어깨 전문의)
- 질문 확장 없는 한국어 검색은 이 설정만으로는 해결 안 됨 → **10-07 의료진 쉬운 말 보강으로 해결** (위 4장). 보강 후에는 검색 설정 차이가 ±1건 수준으로 작아짐
