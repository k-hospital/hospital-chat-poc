## A. 배포·서버 가동 확인 (P1)

GitHub Pages 전환(PR #12·#13), LLM 질문 분류(PR #14), 사내 서버 Docker 배포(2026-10-14) 뒤에 남은 확인 작업이다.

- [ ] **배포된 사이트를 브라우저로 직접 확인** — 주소 `https://k-hospital.github.io/hospital-chat-poc/`
  - 확인: 메인 화면 → AI 상담 버튼 → 챗봇 창이 열리는지 / 오시는 길·증상별 진료 안내가 챗봇 안에서 열리는지 / "새 창" 버튼 / 모바일 폭(375px)
  - 응급 문구("가슴이 너무 아파요" 등)가 119 안내로 가는지 (PR #14로 배포됨)
- [ ] **사내 서버 배포의 마무리 점검** — 서버(리눅스)에 컨테이너 `chatpoc-chatbot`을 올려 접속과 LLM 분류 동작은 확인했다(2026-10-14). 남은 점검:
  - 기존 컨테이너의 이름·가동 시간이 작업 전과 같은지 비교(`docker ps` 결과를 작업 전 목록과 대조)
  - 컨테이너 자동 재시작 설정 확인(`docker inspect chatpoc-chatbot --format '{{.HostConfig.RestartPolicy.Name}}'` → `unless-stopped`). 서버 재부팅 테스트는 다른 서비스에 영향이 있으므로 하지 않는다
  - 로그에 질문 문장이 남지 않는지(`docker compose logs chatbot`에 기능 이름과 시간만)
- [ ] **팀원 PC에서 접속 확인** — `http://<서버 IP>:<CHATPOC_PORT>/`. 접속이 안 되면 서버 방화벽·사내 방화벽 문의
- [ ] **접속 로그인 설정 여부 결정** — 지금은 사내망에서 누구나 접속 가능. 켜려면 서버 `.env`의 `CHATBOT_BASIC_USER`/`CHATBOT_BASIC_PASSWORD`를 채우고 `docker compose up -d --no-deps chatbot`
- [ ] **서버 코드 갱신 절차 정착** — 현재는 `git archive` → `scp` → 풀기 → `docker compose up -d --build --no-deps chatbot`. 서버에서 `git clone`/`git pull`이 가능한지 확인(저장소가 공개라 가능), 담당자와 갱신 책임자 정하기
- [ ] **`docker/chatpoc` 구성 브랜치 공유(push → PR → 머지)** — 공유 전에 반드시 `.env.example`이 **빈 값(자리표시자) 그대로**인지 확인한다. 이 파일에 아이디·비밀번호를 입력한 변경이 로컬 작업 폴더에 남아 있으므로 되돌리고, 실제 값은 서버의 `.env`에만 둔다. 저장소가 공개라 한 번 올라가면 지워도 남는다
- [ ] **임시 파일 정리** — 서버의 `/tmp/chatpoc.tar.gz`, `/tmp/chatpoc_before.txt`, 내 PC의 `chatpoc.tar.gz` (계정 정보는 들어 있지 않음)
- [ ] **이미 ⚙ 설정을 저장한 브라우저의 연결 주소 초기화** — 예전에 저장된 `/pages/...` 값이 새 기본값보다 우선하므로 설정을 비워야 `/hospital-chat-poc/pages/...`로 바뀐다 (팀원 브라우저 안내 필요)
- [ ] **이전 Netlify 사이트 정리** — `ephemeral-parfait-e65ef8`(소유 계정 미확인, 갱신 중단)·검토용 `peppy-strudel` 삭제. 삭제 전에 외부에 공유된 이전 주소가 없는지 확인
- [ ] **PR 정리** — 머지된 브랜치 삭제(`feature/*`, `docs/*`, `fix/*`), 로컬 `main` 최신화

## B. 챗봇 동작 보완 (P2)

- [ ] **추천 질문의 연결 기능이 처음부터 동작하도록 기본 주소 지정** — 진료과 안내·예약 취소·상담원 연결이 지금은 표시되지만 주소가 없으면 "준비중"
  - 방법 1: `linkStore.ts`의 `DEFAULT_LINKS`에 기본 연결 주소 추가 (연결할 화면이 생겼을 때)
  - 방법 2: ⚙ 설정에서 등록 (브라우저마다 따로 저장됨)
- [ ] **서버 없이도 "상담원 연결해줘"가 동작하도록 키워드 규칙에 상담원·콜백 표현 추가** — LLM 서버가 켜져 있으면 이미 동작하고, Pages(규칙 모드)에서만 이동하지 않음
  - 테스트 추가: `intentRouter.test.ts`에 표현 변형(상담원, 사람과 통화, 콜백 등)
- [ ] **질문 입력 → 실제 대화 화면 연결** — 지금은 질문을 판별해 화면으로 이동하거나 한 번의 안내(echo)만 보여 줌. 대화 이력이 쌓이는 화면은 없음

## C. 질문 판별(LLM) 다듬기 (P2)

PR #14로 직접 입력 질문을 사내 LLM이 분류한다(응급 규칙이 먼저, 실패하면 키워드 규칙으로 대체, 복합 질문은 최대 3개를 칩으로).

- [ ] **실제 질문 로그로 재평가** — 지금 평가 문항 121개는 직접 만든 것이라 점수가 낙관적일 수 있다. 팀원이 입력한 질문을 모아 `frontend/scripts/llm-eval/cases.json`에 추가하고 다시 측정
- [ ] **프롬프트·모델 변경 시 회귀 평가** — 프롬프트(`backend/app/features/chat/intent_prompt.txt`)나 모델을 바꾸면 `npx vite-node scripts/llm-eval/run.ts`로 정확도·응답 시간·형식 오류를 먼저 확인
- [ ] **오탐 모니터링** — LLM이 틀렸을 때를 파악할 방법 정하기. 질문 문장은 로그에 남기지 않으므로, 개인정보를 남기지 않는 범위에서 "이동 후 바로 뒤로 간 비율" 같은 지표를 검토
- [ ] **동시 접속 부하 확인** — 평가는 한 번에 1건씩 보낸 시간이다(대형 모델 평균 0.4~0.6초, 서버에 배포된 소형 모델은 평균 0.9초·p95 1.2초). 이 모델은 동시 처리 수가 제한되어 있어 여러 명이 동시에 쓰면 줄을 설 수 있다. 사용자가 늘면 `.env`의 모델 주소만 바꿔 대형 모델로 전환하거나, 대체 모델(`LLM_FALLBACK_*`)을 지정

## D. 음성 입력 (P2)

입력창에 마이크 버튼(`ChatInputBar.tsx`의 `micBtn`)은 자리만 있고 동작하지 않는다.

- [ ] **1단계 — 음성 인식 모듈 (별도 개발)**: 아래 `SpeechInput` 인터페이스에 맞춰 만든다
  ```ts
  interface SpeechInput {
    isSupported(): boolean;
    start(h: { onPartial?(t: string): void; onFinal(t: string): void;
               onError?(r: 'denied' | 'no-speech' | 'network' | 'unknown'): void; onEnd?(): void }): void;
    stop(): void;
  }
  ```
- [ ] **2단계 — 챗봇 연결**: 마이크 버튼 `onClick`, 결과는 `setText`(확인 후 전송) 또는 `onSend`(자동 전송), "듣는 중" 표시, 미지원 브라우저는 버튼 숨김
- [ ] **3단계 — 마이크 권한**: `site/index.html`의 챗봇 iframe에 `allow="microphone"`, 권한 거부 안내, 음성 외부 전송 사내 정책 확인
- [ ] **4단계 — 화면 이동 중 음성 모드 유지**: 연속 인식 + 자동 재시작, 상태는 `App`에서 관리, "듣는 중" 표시·한 번에 끄기, 새로고침·새 창에서는 "음성 모드 다시 켜기" 안내

## E. 안전·보안·운영 전환 (P1~P3)

POC를 실제 서비스로 옮길 때 필요한 일. 지금은 가상 데이터와 브라우저 저장소 기반이다.

**안전 (의료)**
- [ ] **응급 규칙 의료진 검수 (P1)** — `intentRouter.ts`의 `EMERGENCY` 패턴과 LLM 프롬프트의 응급 정의가 병원이 쓰는 응급 판단 기준(응급실 내원 기준, 한국형 응급환자 분류도구 등)과 맞는지 확인. 코드 주석의 "검수 전 임시" 항목(자해, 중독·과다 복용, 아나필락시스, 임신 중 출혈)을 확정하고, 빠진 항목을 추가
- [ ] **극단적 선택·자해 문구의 전용 안내 결정 (P1)** — 지금은 "119 전화"만 나옴. 상담전화 등 전용 안내 문구와 연결 방식을 정해야 함
- [ ] **응급 이중 검사 보강 (P2)** — 지금은 규칙이 먼저 응급이면 바로 안내하고, 규칙이 놓친 응급은 LLM이 잡는다. LLM 서버가 없을 때(Pages)는 규칙만 동작하므로 패턴 보강 범위를 의료진과 정함
- [ ] **증상별 진료 안내 문구 의료진 검수 (P3)** — `public/pages/symptom.html`의 `GUIDE`(추천 진료과·확인 사항·응급 신호)는 샘플 문구

**보안**
- [ ] **서버 접근 통제 보강 (P3)** — 접속 로그인(HTTP Basic)은 선택 기능으로 구현되어 있다(꺼 두면 누구나 접속). 운영 시에는 사내 인증 연동, https(사내 인증서, 리버스 프록시에서 종료), 방화벽 대역 제한, 요청 횟수 제한이 필요
- [ ] **모델 서버의 요청 로그 설정 확인 (P2)** — 모델 서버가 질문 내용을 로그에 남기는지 AI 서버 관리자에게 확인. 앱은 질문 문장을 로그에 남기지 않음
- [ ] **증상 문장의 사내 LLM 전송에 대한 사내 정책 확인 (P2)**

**운영**
- [ ] **연결 주소를 모든 사용자에게 공통 적용** — 지금은 브라우저 `localStorage`라 사용자마다 따로. 백엔드 저장 API로 교체하면 `linkStore.ts`의 `loadLinks`/`saveLinks`만 바꾸면 됨
- [ ] **⚙ 설정 버튼 관리자 제한** — 지금은 누구나 설정 화면을 열 수 있음. 관리자 인증 후에만 노출
- [ ] **메뉴·문구·운영시간을 관리자 콘솔/DB 값으로** — 백엔드 `config/router.py`의 TODO(휴일 캘린더, 메뉴, 면책 문구). 면책 문구는 비워도 기본 문구가 나오는 규칙 유지
- [ ] **서버 운영 방식 확정** — 사내 서버에 Docker 컨테이너로 올려 상시 운영 중(`restart: unless-stopped`). 남은 결정: 모니터링(컨테이너 상태·응답 시간), 로그 보관 기간, 이미지 갱신 주기와 담당자, 서버 자원(디스크·메모리) 점검 방법
- [ ] **서버 네트워크 대역 고정 옵션 (필요 시)** — `chatpoc_net`은 Docker가 자동으로 대역을 할당한다. 이번에는 사내 LLM 서버 대역과 겹치지 않았지만, 다른 컨테이너가 늘어 겹치면 LLM으로 가는 길이 막히므로 그때 대역 고정 설정을 추가
- [ ] **공개 저장소 점검** — 공개(Public)이므로 실제 기관 정보·사내 주소·비밀 값이 올라가지 않았는지 주기적으로 확인. 실제 기관 데이터를 넣기 전에는 비공개 호스팅 또는 별도 저장소로 이전

## F. 문서·자동화 개선 (P4)

- [ ] **작업정리·작업목록 Word 최신화** — 문서를 고칠 때마다 `우리팀_챗봇POC_*.docx`를 다시 만들어 공유 폴더에 반영 (2026-10-14: 사내 서버 배포 반영본)
- [ ] **Docker 이미지 빌드를 CI에서 검증** — 지금 이미지는 서버에서만 빌드해 확인했다. GitHub Actions에서 `docker build`(push 없이)를 돌려 Dockerfile 변경이 서버 배포 전에 걸리게 하기
- [ ] **배포 워크플로 보강** — 실패 시 알림, 빌드 결과(번들 크기) 요약, 의존성 취약점 점검(`npm audit`)
- [ ] **백엔드 테스트를 배포 워크플로에 포함** — 지금 Actions는 프론트 테스트만 실행. `pytest`(30개)도 함께 돌리기
- [ ] **추천 질문 엑셀 변경 PR 자동 검사** — `sync:suggestions` 결과가 커밋된 `suggestions.json`과 같은지 CI에서 확인(엑셀만 고치고 JSON을 안 올리는 실수 방지)
- [ ] **E2E 테스트** — 현재 테스트는 판별기·추천 질문·엑셀 변환·서버 분류 호출 단위 테스트(프론트 100개, 백엔드 30개). 챗봇 창 열기→질문→화면 이동 흐름은 사람이 확인
